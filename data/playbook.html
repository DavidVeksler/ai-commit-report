How one person ships 100 commits a day.

The volume comes from a small set of rules every agent reads before it touches a repo. They are written down, versioned, and enforced by machines where possible.

  1. Runbooks are the spec

    Every repo opens with an AGENTS.md routing table: which doc governs which task. Agents read the smallest path and stop guessing.

  2. Scripts before tokens

    Anything done twice becomes a script. Agents orchestrate scripts instead of re-deriving what code can compute, which keeps runs fast and cheap.

  3. The night shift

    Recurring judgment work runs as scheduled routines between 1 and 5 AM, each with hard limits, per-run caps and a fail-closed rule.

  4. Git is the safety net

    Agents commit and push without asking, in small commits. History is the backup and the audit log. Deployment is the one human approval gate.

  5. Rules become gates

    A rule an agent might forget becomes a pre-push hook or a build-failing lint. Machines enforce it every time.

  6. Right model, right job

    Haiku for bulk mechanical work, Sonnet for volume, Opus for judgment, Fable for specs that cheaper models then implement.
